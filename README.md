# 나만의 퀴즈 게임 — 영화 / 시네마

터미널에서 동작하는 영화 주제 퀴즈 게임. Python 기본 문법 + 객체지향(클래스) +
JSON 파일 영속성으로 구현했다. 프로그램을 종료했다가 다시 켜도 추가한 퀴즈와 최고
점수가 유지된다.

- **저장소:** `https://github.com/SSUNOWL/codyssey-week1-quiz-game` · 제출 브랜치: **`main`**
- **실행:** `python main.py` (Python 3.10 이상, 표준 라이브러리만 사용)

---

## 1. 프로젝트 개요

메뉴에서 번호를 선택하면 **퀴즈 풀기 / 추가 / 목록 / 점수 확인 / 삭제 / 종료**가
분기 실행되는 콘솔 프로그램이다. 개별 문제는 `Quiz` 클래스, 게임 전체 흐름은
`QuizGame` 클래스로 역할을 나눴고, 데이터는 프로젝트 루트 `state.json`에 UTF-8로
저장·복원한다. 잘못된 입력·강제 종료(Ctrl+C)·파일 손상 상황에서도 프로그램이
비정상 종료하지 않도록 방어 처리했다.

## 2. 퀴즈 주제 선정 이유 — 영화 / 시네마

- **누구나 아는 공통 화제**라 문제를 만들기도, 함께 즐기기도 쉽다. 감독·수상·캐릭터 등
  난이도(쉬움~어려움)를 자연스럽게 섞을 수 있어 퀴즈 주제로 적합하다.
- 봉준호(기생충)·제임스 카메론(타이타닉/아바타)처럼 **사실 기반의 명확한 정답**이
  존재해 정오답 판정이 애매하지 않다.
- 개인적으로 영화를 좋아해 문제 지문·힌트를 **직접 쓰기 즐거운** 주제였다.

## 6. 데이터 파일 설명 — `state.json`

- **경로:** 프로젝트 루트 `./state.json` (실행 위치 기준)
- **역할:** 퀴즈 목록·최고 점수·게임 기록을 저장해 **재시작 후에도 데이터 유지**
- **인코딩:** UTF-8 (`ensure_ascii=False`로 한글 그대로 저장)
- **없을 때:** 기본 퀴즈 6문항으로 시작 · **손상 시:** 안내 후 기본 데이터로 복구
- **버전 관리:** 런타임 데이터이므로 `.gitignore`로 제외(코드에 기본값 내장)

**스키마**

```json
{
  "quizzes": [
    { "question": "영화 '기생충'의 감독은?",
      "choices": ["박찬욱", "봉준호", "김기덕", "이창동"],
      "answer": 2,
      "hint": "2019년 칸 영화제 황금종려상 수상작입니다." }
  ],
  "best_score": 80,
  "history": [
    { "datetime": "2026-07-28 18:36:30", "total": 5, "correct": 4, "score": 80 }
  ]
}
```

| 키 | 의미 |
|----|------|
| `quizzes` | 퀴즈 목록(문제·선택지 4개·정답 번호 1~4·힌트) |
| `best_score` | 최고 점수(백분율). 아직 안 풀었으면 `null` |
| `history` | 게임 기록(날짜시간·문항 수·정답 수·점수) *(보너스)* |

### 6-1. 왜 JSON을 골랐나 (형식 선택 근거)

- **가독성** — `indent=2` + `ensure_ascii=False`라 메모장으로 열면 한글 문제와 정답이 그대로 보인다.
  저장 파일을 설명·시연해야 하는 과제라 "열어서 바로 보여줄 수 있는 형식"이 중요했다.
- **경량 텍스트 포맷** — 1문항이 약 370바이트다. 스키마 선언·서버·드라이버 없이 **파일 하나**로 끝난다.
- **표준 라이브러리만으로 완결** — `import json` 한 줄. 외부 설치가 0이라 실행 조건("표준 라이브러리만 사용")과 맞는다.
- **파이썬 자료구조와 1:1 대응** — `dict/list/str/int`가 그대로 매핑돼 `to_dict`/`from_dict`가 각각 대여섯 줄이면 된다.
- **버린 대안** — 자체 텍스트 포맷(파서를 직접 짜야 하고 선택지에 구분자가 들어가면 깨짐) ·
  CSV(선택지 4개 같은 중첩 구조를 표현 못 함) · pickle(사람이 읽을 수 없고 버전 호환·보안 문제) ·
  SQLite(현재 규모에는 과함 — 전환 기준은 §6-3).

### 6-2. 손상 대응과 백업 정책

- **정책: 자동 백업 파일을 만들지 않는다.** 손상이 감지되면 원인 메시지를 그대로 출력하고
  기본 퀴즈 6문항으로 복구해 게임을 계속한다(`load()`).
- **알고 있어야 할 점:** 복구 후 추가·삭제·풀기·정상 종료 중 하나라도 하면 `save()`가
  **손상된 원본을 덮어쓴다.** 원본을 살펴보려면 그 전에 먼저 복사해야 한다.

  ```bash
  cp state.json state.json.bak    # 조사 전에 원본 확보
  python -m json.tool state.json  # 어느 줄에서 깨졌는지 확인
  ```

- **왜 자동 백업을 넣지 않았나** — 기본 퀴즈는 코드에 내장되어 언제든 재생성되고, 잃는 것은
  사용자가 직접 추가한 문제와 기록뿐이다. 백업 파일의 이름·개수·정리 주기를 관리하는 코드는
  이 규모에 비해 비용이 크다고 봤다.
- **넣는다면** `load()`의 `except`에서 `os.replace(self.path, self.path + ".bak")` 한 줄이면
  마지막 손상본 하나는 보존된다. 지금은 의도적으로 넣지 않은 상태다.

### 6-3. 퀴즈가 1000개로 늘어나면 (한계와 전환 기준)

이 저장소 코드로 1000문항을 실제로 만들어 측정한 값이다.

| 항목 | 1000문항 | 비고 |
|------|----------|------|
| 파일 크기 | 약 **360 KB** (문항당 368 B) | `ensure_ascii=False` + `indent=2` 기준 |
| 시작 로드 | 약 **34 ms** | 파일 읽기 + `Quiz` 객체 1000개 복원 |
| 저장 1회 | 약 **32 ms** | 전체 재직렬화 + 쓰기 |
| 메모리 | 약 **0.71 MB** | `Quiz` 객체 1000개 |

**구조상 한계 3가지**

1. **전량 적재** — 시작할 때 전체를 메모리에 올린다(시간·메모리 모두 O(N)). 1000개는 체감이 없지만
   10만 개면 로드가 수 초, 메모리가 수십 MB로 늘어난다.
2. **전체 재작성 저장** — 한 문제를 추가·삭제해도 **파일 전체**를 다시 쓴다(변경 1건에 O(N)).
   쓰는 도중 프로세스가 죽으면 파일이 잘릴 수 있다(원자적 쓰기가 아님).
3. **검색과 식별자 없음** — 지문으로 찾으려면 선형 탐색 O(N)이고, 삭제는 화면 번호(리스트 위치)
   기준이라 1000줄을 스크롤해야 한다. 목록도 한 번에 1000줄이 쏟아진다(페이징 없음).

**먼저 할 개선(코드 소폭)** — 목록 페이징 + 키워드 필터, 퀴즈마다 고유 `id`를 부여해 위치가 아닌 id로 삭제.

**전환 기준** — 수천 개를 넘거나 **부분 갱신·검색·동시 접근**이 필요해지면 표준 라이브러리 `sqlite3`로 옮긴다.
인덱스로 검색이 O(log N)이 되고, 한 행만 `UPDATE` 하므로 전체 재작성이 사라지며, 트랜잭션이 쓰기 도중
손상을 막아준다. 지금 규모(수십 개)에서는 파일 하나가 더 단순해 JSON을 유지한다.

### 8-1. 설계 결정 (Why)

> 동료 평가는 "왜 그렇게 했는지"를 묻는다. 비자명한 선택을 근거·버린 대안과 함께 정리한다.

| 결정 | 선택한 방식 | 왜(근거) | 버린 대안 |
|------|-------------|----------|-----------|
| 역할 분리 | 클래스 2개 — `Quiz`(한 문제) / `QuizGame`(게임 상태·흐름) | 데이터+검증+직렬화는 문제 단위로, 상태·메뉴·파일 IO는 게임 단위로 응집(단일 책임) | 전역 리스트 + 함수 뭉치(상태 추적·재사용 어려움) |
| 정답 표현 | 정답을 **1~4 번호**로 저장(`Quiz.answer`) | 선택지 텍스트가 편집돼도 정답이 안 흔들리고, `is_correct`가 int 비교라 단순 | 정답 문자열 비교(대소문자·공백·중복 텍스트에 취약) |
| 입력 검증 | 공통 규칙을 `helpers.read_int/read_nonempty`로 분리 | 공백·숫자·범위·빈입력 규칙을 한 곳에 모아 메뉴 선택·문제 수·삭제 번호·퀴즈 추가에서 재사용 | 호출부마다 `try/except` 반복(누락·불일치) |
| 정답 입력 | 별도 루프 `_read_answer` | 정답은 `1-4`뿐 아니라 `h`(힌트)도 받아야 해 helpers로는 부족 → 같은 검증 규칙을 여기서 적용 | 힌트 처리를 위해 helpers를 복잡하게 만드는 것 |
| 손상 데이터 | `load()`에서 예외를 잡고 `isinstance(data, dict)`로 최상위 구조까지 검사해 기본 퀴즈로 복구 | 파일 없음·깨진 JSON·최상위 비객체(`[]`/`null`)·일부 필드 오류(예: `quizzes`가 숫자)에서 죽지 않고 플레이 가능 | 예외 미처리(첫 줄에서 크래시) |
| 힌트 정책 | 힌트 사용 시 그 문제는 점수 제외(`used_hint`) | 힌트에 비용을 부여해 게임성 유지 | 감점 없는 힌트(난이도 의미 없음) |
| 점수 척도 | 정답/총문제 × 100의 **백분율(int)** | 푼 문제 수가 달라도 같은 0~100 척도로 비교(원점수보다 비교 쉬움) | 원점수(문제 수 다르면 비교 불가) |
| 랜덤 출제 | `random.sample(quizzes, count)` | 비복원 추출이라 **같은 항목을 두 번 뽑지 않고** count개 선택·순서 섞임 | `random.choice` 반복(같은 항목이 다시 뽑힐 수 있음) |

### 8-2. 파일을 이렇게 나눈 기준 (모듈 분리 근거)

**분리 기준은 "함께 바뀌는 것끼리 묶는다"이다.** 문제 수를 늘리는 일, 입력 규칙을 고치는 일,
메뉴 흐름을 바꾸는 일은 서로 다른 이유로 발생하므로 서로 다른 파일에 두었다.

**의존 방향 (화살표 = import, 순환 없음)**

```text
main.py
   └─> quiz_game.py ─┬─> quiz.py            (Quiz 클래스)
                     ├─> default_quizzes.py ─> quiz.py
                     └─> helpers.py          (아무것도 import 하지 않음)
```

- 화살표는 **위에서 아래 한 방향뿐**이다. `quiz.py`는 `quiz_game.py`를 모르고, `helpers.py`는
  이 프로젝트의 어떤 모듈도 모른다. 아래쪽 파일일수록 독립적이라 따로 떼어 읽고 테스트할 수 있다.
- 순환 import가 없으므로 어떤 파일을 먼저 읽어도 이해가 막히지 않는다.

| 파일 | 한 문장 책임 | 이 파일이 수정되는 이유 | 일부러 여기 두지 않은 것 |
|------|--------------|------------------------|--------------------------|
| `main.py` | 프로그램을 시작하고 **끝까지 안전하게 끝내는** 일 | 시작/종료 방식이 바뀔 때 | 게임 규칙(모두 `quiz_game.py`) |
| `quiz.py` | **한 문제**의 데이터·유효성·직렬화 | 문제의 구성 요소가 바뀔 때(예: 선택지 5개) | 화면 출력(`print`)·파일 IO |
| `default_quizzes.py` | 초기 문제 **데이터** | 문제를 추가·수정할 때 | 로직 일절 없음 |
| `helpers.py` | 입력을 **검증해서 받아오는** 규칙 | 입력 처리 규칙이 바뀔 때 | 게임 상태·종료 처리 |
| `quiz_game.py` | 게임 **상태와 흐름**(메뉴·기능·저장) | 기능이 늘거나 흐름이 바뀔 때 | 한 문제의 내부 규칙(→`quiz.py`) |

**한 파일에 다 넣지 않은 이유** — 전부 `main.py`에 넣으면 300줄짜리 파일 하나가 되고,
"선택지 개수 4"·"입력 검증"·"저장 형식"이 함수 사이에 흩어져 한 곳을 고칠 때 나머지를
전부 훑어야 한다. 지금 구조에서는 *문제를 추가*하려면 `default_quizzes.py`만, *입력 규칙*을
고치려면 `helpers.py`만 열면 된다.

### 8-3. 실행 흐름 (시작 → 메뉴 → 종료)

**① 시작 시퀀스**

```text
python main.py
  → main()                      # main.py
      → _enable_utf8()          # 콘솔을 UTF-8로 (한글·이모지 보호)
      → QuizGame()              # quiz_game.py
          → __init__()          # 속성 초기화 후
              → load()          # state.json 읽기 or 기본 퀴즈
                                #   → Quiz.from_dict() 로 dict → Quiz 복원
      → game.run()              # 메뉴 루프 진입
```

> 저장 데이터 안내 문구("저장된 데이터를 불러왔습니다")가 **메뉴보다 먼저** 출력되는 이유가 여기 있다.
> `load()`는 `run()`이 아니라 `__init__` 안에서 실행되므로, 객체가 만들어진 순간 이미 사용 가능한 상태다.

**② 메뉴 루프** (`QuizGame.run()`)

```text
while True:
    show_menu()                       # 메뉴 출력
    choice = read_int("선택: ", 1, 6) # ← 여기서 이미 1~6만 통과
    1 → play()  2 → add_quiz()  3 → list_quizzes()
    4 → show_score()  5 → delete_quiz()
    6 → 안내 출력 → save() → break    # 유일한 정상 탈출구
```

`run()`에 "잘못된 메뉴입니다" 분기가 **없는 것이 정상이다.** 범위 밖·문자·빈 입력은
`read_int`가 자기 루프 안에서 되묻고 유효한 값만 돌려주므로, `run()`에 도달한 값은 항상 1~6이다.
검증을 한 층 아래로 내려 흐름 코드를 깨끗하게 유지한 것이다.

**③ "퀴즈 풀기"(메뉴 1) 상세 흐름** — 이 프로그램에서 가장 긴 경로

```text
play()
 1. 퀴즈가 0개면  → 안내 후 즉시 return            (빈 목록 가드)
 2. read_int("몇 문제를…", 1, 등록수)              → count 확정 (보너스: 문제 수 선택)
 3. random.sample(self.quizzes, count)             → 비복원 추출 (보너스: 랜덤 출제)
 4. for number, quiz in enumerate(selected, 1):
      ├ quiz.render(number)  출력                  (Quiz가 문자열만 만들고, print는 여기서)
      ├ _read_answer(quiz)   → (선택번호, 힌트사용여부)
      │    └ 'h' 입력 시 힌트 출력 + used_hint=True → 계속 되물음  (보너스: 힌트)
      └ is_right = is_correct(choice)  →  is_right and not used_hint → correct += 1
 5. score = int(correct / count * 100)             → 백분율 환산
 6. best_score is None or score > best_score       → 최고 점수 갱신
 7. history.append({datetime, total, correct, score})  (보너스: 기록)
 8. save()                                         → state.json 즉시 반영
```

**④ 나머지 기능의 흐름 요약**

| 메뉴 | 흐름 | 끝나고 저장하나 |
|------|------|-----------------|
| 2 추가 | `read_nonempty`×5 + `read_int`(정답) + `input`(힌트, 선택) → `Quiz(...)` 생성 → 목록에 append | 예 |
| 3 목록 | 빈 목록 가드 → `enumerate(…, 1)`로 번호와 함께 출력 | 아니오(읽기 전용) |
| 4 점수 | `best_score is None` 가드 → 최고 점수 + `history[-5:]` 출력 | 아니오(읽기 전용) |
| 5 삭제 | `list_quizzes()` 재사용 → 번호 입력 → `pop(number-1)` | 예 |
| 6 종료 | 인사 출력 → `save()` → `break` | 예 |

**⑤ 비정상 종료 경로** — `Ctrl+C`(KeyboardInterrupt)나 입력 종료(EOF)는 어느 `input()`에서
발생하든 아무도 잡지 않고 **`main()`의 `try`까지 그대로 올라온다.** 거기서 한 번만 잡아
안내 후 `game.save()`를 호출하므로, 어떤 화면에서 강제 종료해도 데이터는 남는다.

### 8-4. 파일별 구현 근거와 동작 방식

#### `main.py` — 진입점

| 코드 | 무엇을 하나 | 왜 이렇게 했나 |
|------|-------------|----------------|
| `_enable_utf8()` | `sys.stdout/stdin.reconfigure(encoding="utf-8")` | 윈도우 콘솔 기본 인코딩(cp949)에서 이모지·일부 한글이 깨져 실행이 중단되는 것을 막는다 |
| 그 안의 `except Exception: pass` | 실패해도 무시 | `reconfigure`는 환경(리다이렉트된 스트림 등)에 따라 없을 수 있는데, **인코딩 설정 실패로 게임을 못 하게 만들 이유가 없다.** 부가 기능이라 조용히 넘어간다 |
| `try: game.run() except (KeyboardInterrupt, EOFError)` | 중단 신호를 최상위에서 한 번만 처리 | `input()`은 `helpers`·`_read_answer` 등 여러 곳에 흩어져 있다. 각자 잡으면 코드가 중복될 뿐 아니라, **중단 신호를 잡고도 다시 루프로 되돌아가 못 빠져나오는** 문제가 생긴다. 종료 책임을 한 곳에 모았다 |
| `game.save()` (except 블록 안) | 중단 시에도 저장 | 정상 종료(메뉴 6)와 강제 종료의 데이터 보존 수준을 같게 맞춘다 |
| `if __name__ == "__main__":` | 직접 실행할 때만 `main()` | 다른 모듈이 `import main` 해도 게임이 멋대로 시작되지 않는다 |

#### `quiz.py` — 한 문제를 표현하는 클래스

**왜 dict가 아니라 클래스인가** — 한 문제는 `question·choices·answer·hint` 네 값이 **항상 함께**
다니고, "이 답이 맞나?"·"화면에 어떻게 보이나?"라는 **동작이 그 데이터에 붙어 있다**. dict로 두면
`q["choices"][q["answer"]-1]` 같은 코드가 호출부마다 흩어지고, 필드 이름 오타를 실행 전에 잡을 수 없다.

| 요소 | 동작 방식 | 구현 근거 |
|------|-----------|-----------|
| `CHOICE_COUNT = 4` (클래스 상수) | 선택지 개수의 유일한 출처 | 숫자 `4`가 검증·프롬프트 문구·`add_quiz`의 `range`에 흩어지는 매직 넘버가 된다. `quiz_game.py`도 `Quiz.CHOICE_COUNT`를 참조하므로 이 값만 바꾸면 전부 따라온다 |
| `__init__`의 검증 5종 | 빈 지문·개수 불일치·빈 선택지·정답 범위·정수 변환을 확인하고 실패 시 `ValueError` | **객체가 만들어지는 순간부터 항상 유효**함을 보장한다. 덕분에 `render`·`is_correct`에는 방어 코드가 한 줄도 필요 없다 |
| `str(question).strip()`, `answer = int(answer)` | 타입을 강제 변환 | JSON에 `"2"`처럼 문자열로 저장돼 있어도 복원되고, `"abc"`처럼 복원 불가능하면 `ValueError`가 나 **`load()`가 손상으로 처리**한다 |
| `render(index)`가 `print`가 아니라 **문자열을 반환** | 문제 지문+선택지를 한 문자열로 조립해 돌려줌 | 출력(“어디에 찍을지”)은 호출부의 관심사다. 문자열을 돌려주면 테스트에서 결과를 그대로 비교할 수 있고, `Quiz`가 콘솔에 묶이지 않는다 |
| `enumerate(self.choices, start=1)` | 0-based 리스트를 1-based 화면 번호로 | 사용자에게 보이는 번호와 내부 인덱스의 변환 지점을 한 줄로 고정한다 |
| `is_correct(choice)` → `int(choice) == self.answer` | 번호끼리 비교 | 정답을 **텍스트가 아니라 번호로** 저장했기 때문에 가능한 단순 비교다(§8-1 참고) |
| `has_hint()` → `bool(self.hint)` | 힌트 유무 판정 | 힌트 없음을 `None`이 아니라 **빈 문자열**로 표현했다. `None` 검사와 문자열 연산을 섞지 않아도 되고, `strip()`을 그대로 쓸 수 있다 |
| `to_dict()` / `from_dict()` 한 쌍 | Quiz ↔ dict 변환 | 저장 형식에 대한 지식을 `Quiz` 안에 가둔다. `QuizGame`은 `"question"` 같은 **키 이름을 전혀 몰라도** 저장·복원할 수 있다 |
| `from_dict`가 `@classmethod` | 인스턴스 없이 `Quiz.from_dict(d)`로 호출 | dict로부터 **새 인스턴스를 만들어 주는 팩토리**라 `self`가 아니라 `cls`를 받는 것이 자연스럽다. `cls(...)`를 거치므로 `__init__`의 검증도 자동으로 통과해야 한다 |
| `data["question"]` vs `data.get("hint", "")` | 필수 필드는 `[]`, 선택 필드는 `.get()` | 필수 필드가 없으면 `KeyError`가 나 손상으로 처리되어야 **하고**, 힌트는 없어도 정상이라 기본값을 준다 |

#### `default_quizzes.py` — 초기 데이터

- **로직과 데이터를 분리한 이유:** 문제를 늘리거나 고칠 때 게임 로직 파일을 건드릴 필요가 없다.
  이 파일에는 `Quiz(...)` 생성 외에 어떤 로직도 없다.
- **왜 리스트 상수가 아니라 함수인가:** 모듈 레벨에 `DEFAULT = [...]`로 두면 **모두가 같은 리스트
  객체를 공유**한다. 손상 복구로 그 리스트를 받아 쓴 뒤 사용자가 퀴즈를 추가·삭제하면 원본 기본값까지
  변형되어, 다음 복구 때 "기본 퀴즈"가 더 이상 기본이 아니게 된다. 함수로 두어 **호출할 때마다
  새 리스트와 새 `Quiz` 인스턴스**를 만들어 이 문제를 원천 차단했다.
- **6문항인 이유:** 과제 요구가 5개 이상이라 여유를 두고 6개를 넣었다.

#### `helpers.py` — 입력 검증

- **왜 클래스가 아니라 함수 모음인가:** 이 모듈에는 **유지할 상태가 없다.** 입력을 받아 검증하고
  값을 돌려주면 끝이라 `self`가 필요 없다. 상태 없는 동작에 클래스를 씌우는 것은 과한 추상화다.

```python
def read_int(prompt, low, high):
    while True:
        raw = input(prompt).strip()   # ① 앞뒤 공백 제거
        if raw == "": ... continue    # ② 빈 입력
        try: value = int(raw)
        except ValueError: ... continue  # ③ 숫자 아님
        if not low <= value <= high: ... continue  # ④ 범위 밖
        return value                  # 유효한 값일 때만 탈출
```

| 구현 선택 | 근거 |
|-----------|------|
| `while True` + `continue`, `return`으로만 탈출 | 유효한 값을 얻기 전에는 **절대 호출부로 돌아가지 않는다**는 계약이 코드 모양으로 드러난다. 호출부는 반환값을 무조건 신뢰할 수 있다 |
| ②③④를 **각각 다른 메시지**로 안내 | "잘못된 입력입니다" 하나로 뭉치면 사용자가 무엇을 고쳐야 할지 모른다 |
| `str.isdigit()` 대신 `int()` + `try/except` | `isdigit()`은 `"-3"`을 거부하고 일부 유니코드 숫자를 통과시킨다. **실제로 변환해 보는 것**이 가장 정확한 판정이다 |
| `low`, `high`를 매개변수로 | 메뉴(1~6)·문제 수(1~N)·정답 번호(1~4)·삭제 번호(1~N)가 **같은 함수 하나**를 재사용한다 |
| `KeyboardInterrupt`/`EOFError`를 **여기서 잡지 않음** | 여기서 잡으면 `while True`가 계속 돌아 Ctrl+C로 빠져나갈 수 없게 된다. 종료는 `main.py`의 책임(모듈 docstring에도 명시) |
| `read_nonempty` | 문제 지문·선택지처럼 "비어 있으면 안 되는 텍스트" 전용. `strip()` 결과가 빈 문자열이면 되묻는다 |

> 이 모듈에는 위 **두 함수만** 있다. 한때 메뉴 입력 전용 래퍼(`read_menu_choice`)를 두었지만
> `read_int`에 그대로 위임하기만 하고 호출부가 없어 제거했다. 이름만 다른 통로를 남겨두면
> 읽는 사람이 "이 둘은 뭐가 다른가"를 확인해야 하므로, 쓰이지 않는 추상화는 남기지 않았다.

#### `quiz_game.py` — 상태와 흐름

**상태를 인스턴스 속성으로 둔 이유:** `quizzes`·`best_score`·`history`는 여러 메서드가 함께 읽고
쓴다. 전역 변수로 두면 누가 언제 바꾸는지 추적이 어렵지만, `self`에 묶으면 **상태를 만지는 코드가
이 클래스 안으로 한정**된다.

| 요소 | 동작 방식 | 구현 근거 |
|------|-----------|-----------|
| `DATA_PATH = "state.json"` + `def __init__(self, path=DATA_PATH)` | 기본 경로를 상수로 두고 매개변수로 주입 가능하게 | 평소에는 `QuizGame()`으로 충분하고, 필요하면 다른 경로를 넘겨 실제 데이터를 건드리지 않고 시험할 수 있다 |
| `__init__` 끝에서 `self.load()` | 생성과 동시에 상태 복원 | "객체는 만들어지면 바로 쓸 수 있어야 한다". 호출부가 `load()`를 잊는 실수가 불가능해진다 |
| `load()` 1단계: `os.path.exists` | 파일이 없으면 안내 후 기본 퀴즈 | **첫 실행은 오류가 아니다.** 손상(⚠️)과 다른 문구(📂)로 구분해 사용자를 놀라게 하지 않는다 |
| `load()` 2단계: `isinstance(data, dict)` 검사 후 직접 `raise ValueError` | 최상위가 `[]`나 `null`이면 손상 처리 | `[]`·`null`도 **문법상 유효한 JSON**이라 `json.load`는 통과한다. 그대로 두면 `data.get()`에서 `AttributeError`가 나는데 이는 아래 `except` 목록에 없어 프로그램이 죽는다. 명시적으로 `ValueError`를 던져 **같은 복구 경로로 흘려보낸다** |
| `load()` 3단계: `except (JSONDecodeError, OSError, ValueError, KeyError, TypeError)` | 5종을 한 번에 잡아 기본값 복구 | 각각 실제 시나리오가 있다 — 문법 깨짐(`JSONDecodeError`), 읽기 권한·디스크 오류(`OSError`), `Quiz` 검증 실패·`int()` 변환 실패(`ValueError`), 필수 필드 누락(`KeyError`), `quizzes`가 리스트가 아니라 순회 불가(`TypeError`) |
| 로컬 변수에 담았다가 `try` **밖에서** `self`에 대입 | `quizzes`/`best_score`/`history`를 먼저 지역 변수로 만든다 | 도중에 예외가 나도 **self가 절반만 덮인 어중간한 상태가 되지 않는다.** 전부 성공했을 때만 한꺼번에 교체 |
| `int(raw_best) if isinstance(raw_best, (int, float)) else None` | 숫자일 때만 최고 점수로 인정 | 아직 안 푼 상태(`null`)와 손상된 값(`"abc"`)을 모두 "기록 없음"으로 흘린다. (`bool`이 `int`의 하위형이라 `true`는 1점으로 들어오지만, 사람이 파일을 직접 그렇게 고친 경우뿐이라 허용 범위로 봤다) |
| `self.quizzes = quizzes if quizzes else default_quizzes()` | 파일의 퀴즈가 0개면 기본값 | 퀴즈가 하나도 없으면 아무 메뉴도 의미가 없어 빈 껍데기 게임이 된다 (한계는 §8-7 참고) |
| `save()`의 `ensure_ascii=False` | 한글을 `\uXXXX` 대신 그대로 저장 | 저장 파일을 사람이 열어 확인하는 것이 과제 요구사항이다 |
| `save()`의 `indent=2` | 줄바꿈·들여쓰기 적용 | 위와 같은 이유. 파일 크기보다 가독성이 중요하다 |
| `save()`가 `OSError`**만** 잡음 | 쓰기 실패만 안내하고 계속 진행 | 직렬화 자체가 실패하는 상황은 코드 버그이므로 조용히 삼키면 안 된다. 잡을 이유가 분명한 예외만 잡는다 |
| `save()` 호출 시점: 풀기 끝·추가·삭제·정상 종료·강제 종료 | 상태가 바뀌는 **모든 지점에서 즉시** 저장 | 종료 경로가 어디든 데이터가 남는다. 매번 파일 전체를 다시 쓰지만 수십 KB 수준이라 체감 비용이 없다 |
| `best_score_text()` | `None` → `"아직 없음"`, 아니면 `"N점"` | 점수를 문구로 바꾸는 규칙을 한 곳에 모았다. `load()`·`play()`·`show_score()` 세 곳이 이 메서드를 써서 같은 표현이 유지된다 |
| `_read_answer()`가 `helpers`가 아닌 이곳에 있는 이유 | 정답 입력 전용 루프 | 정답은 `1~4`뿐 아니라 **`h`(힌트)** 도 받아야 하고, 반환값이 `(번호, 힌트사용여부)` **튜플**이라 `read_int`의 계약과 맞지 않는다. 억지로 합치면 `read_int`가 힌트를 아는 이상한 함수가 된다 |
| `_read_answer`의 `used_hint = while 루프 바깥` 선언 | 힌트를 본 뒤 `continue`로 다시 입력받아도 값 유지 | 루프 안에서 초기화하면 힌트를 보고 답을 입력하는 순간 사용 사실이 사라져 점수 정책이 무력화된다 |
| `.strip().lower()` | `" H "`도 힌트로 인식 | 대소문자·공백 때문에 사용자가 좌절하지 않게 한다 |
| `_` 접두사(`_read_answer`, `_use_defaults`) | 내부 전용 표시 | 파이썬 관례로 "클래스 밖에서 부르지 말 것"을 알린다 |
| `random.sample(self.quizzes, count)` | 비복원 추출 | `count`개를 **중복 없이** 뽑고 순서까지 섞인다. `random.choice`를 반복하면 같은 문제가 다시 나올 수 있다 |
| `is_right = quiz.is_correct(choice)` 후 3분기 | 정답 판정은 **한 번만** 하고 `is_right`/`used_hint` 조합으로 갈래를 나눔 | "정답이면서 힌트를 안 봤을 때만 득점"이라는 정책이 그대로 드러나고, 같은 판정을 두 번 하지 않는다 |
| `int(correct / count * 100)` | 백분율(소수점 버림) | `count`는 `read_int(..., 1, N)`이 1 이상을 보장하므로 0으로 나눌 일이 없다 |
| `best_score is None or score > best_score` | 최고 점수 갱신 조건 | `None`을 숫자와 비교하면 `TypeError`가 나므로 `is None`을 **먼저** 두었다. 파이썬의 단축 평가 덕에 뒷 조건은 안전할 때만 실행된다 |
| `add_quiz()`의 리스트 컴프리헨션 | `[read_nonempty(f"선택지 {i}: ") for i in range(1, Quiz.CHOICE_COUNT + 1)]` | 같은 코드를 4번 복붙하지 않고, 선택지 개수는 `Quiz`의 상수를 따른다 |
| `add_quiz()`의 `try: Quiz(...) except ValueError` | 생성 실패 시 안내 후 취소 | `read_nonempty`가 이미 빈 값을 막지만, **최종 관문은 `Quiz`의 검증**이다. 나중에 입력 규칙이 바뀌어 틈이 생겨도 잘못된 퀴즈가 목록에 들어가지 않는다 |
| 힌트만 `read_nonempty`가 아닌 `input()` | 그냥 Enter를 허용 | 힌트는 선택 입력이다. 여기에 빈 값 금지를 적용하면 힌트 없는 문제를 만들 수 없다 |
| `delete_quiz()`가 `list_quizzes()`를 재사용 | 삭제 전 목록을 그대로 출력 | 화면에 보이는 번호와 입력할 번호가 **같은 코드에서 나온다.** 번호 체계가 어긋날 수 없다 |
| `self.quizzes.pop(number - 1)` | 1-based 입력을 0-based 인덱스로 | 변환이 한 곳에만 있다. 범위는 `read_int(..., 1, len(...))`가 이미 보장 |
| `show_score()`의 `history[-5:]` | 최근 5개만 출력 | 기록이 5개 미만이어도 슬라이스는 오류 없이 있는 만큼만 돌려준다 |
| 각 기능 첫 줄의 빈 목록/미플레이 가드 | 안내 후 `return` | 데이터가 없을 때 빈 화면이나 오류 대신 **다음에 뭘 하면 되는지**를 알려준다 |

### 8-5. 데이터 흐름 (메모리 ↔ 파일)

```text
[입력/기본값]            [메모리]              [파일]
사용자 입력 ─ add_quiz ─┐
                        ├─> list[Quiz] ─ to_dict() ─> dict ─ json.dump ─> state.json
default_quizzes() ──────┘      ▲                                             │
                               └── from_dict() <── dict <── json.load ◀──────┘
```

- 프로그램이 도는 동안 퀴즈는 **항상 `Quiz` 객체**이고, 파일에 닿는 순간에만 dict로 바뀐다.
  변환 지점이 `to_dict`/`from_dict` 두 곳뿐이라 저장 형식이 바뀌어도 고칠 곳이 명확하다.
- `best_score`·`history`는 원래부터 JSON이 그대로 표현할 수 있는 값(숫자·리스트/딕셔너리)이라
  변환 없이 오간다. 굳이 클래스를 만들지 않았다.

### 8-6. 검증·예외 처리의 3중 구조

| 층 | 위치 | 막는 것 | 실패했을 때 |
|----|------|---------|-------------|
| 1층 · 입력 | `helpers.read_int/read_nonempty`, `_read_answer` | 공백·빈 입력·숫자 아님·범위 밖 | 안내 후 **재입력**(진행 안 함) |
| 2층 · 객체 | `Quiz.__init__` | 잘못된 문제 구성(빈 지문, 선택지 개수·정답 범위) | `ValueError` → 추가 취소 / 로드 시 복구 |
| 3층 · 파일·프로세스 | `QuizGame.load/save`, `main.py` | 파일 없음·손상·쓰기 실패·Ctrl+C·EOF | 안내 후 **기본값 복구 또는 저장 후 안전 종료** |

설계 원칙은 **"각 층은 자기가 책임질 수 있는 것만 잡는다"** 이다. 그래서 `helpers`는 중단 신호를
잡지 않고(잡으면 종료 불가), `save()`는 `OSError`만 잡으며(그 외는 코드 버그), 프로세스 종료는
`main.py` 한 곳에서만 처리한다.

### 8-7. 알려진 트레이드오프와 한계 (의도적으로 남긴 것)

| 사항 | 현재 동작 | 왜 이대로 두었나 |
|------|-----------|------------------|
| 퀴즈를 전부 삭제하면 | 다음 실행 때 기본 6문항이 되살아난다(`quizzes if quizzes else default_quizzes()`) | "퀴즈 0개인 게임"보다 낫다고 판단했다. 사용자가 **의도적으로 비운 상태를 유지할 수 없다**는 것이 대가다 |
| 같은 문제 중복 등록 | 막지 않는다 | 중복 판정 기준(지문만? 선택지까지?)이 애매하고 과제 요구가 아니다. 중복 등록하면 랜덤 출제에서 나란히 뽑힐 수 있다 |
| 점수 척도 | 백분율이라 3문제일 때 눈금이 0·33·67·100으로 굵다 | 문제 수가 달라도 한 척도로 비교하는 이점이 더 크다고 봤다 |
| 저장 방식 | 변경마다 파일 **전체**를 다시 쓴다 | 데이터가 수십 KB 규모라 증분 저장의 복잡도를 들일 이유가 없다 |
| `history` 항목의 내부 구조 | `load()`가 검사하지 않는다 | 사람이 `state.json`을 직접 고쳐 기록 항목의 키를 지운 경우에만 문제가 된다. 이 한 가지를 위해 검증 코드를 늘리기보다 한계로 남겼다 |

## 11. 트러블슈팅

### 1) 저장 파일(`state.json`)이 손상되면 다음 실행이 통째로 종료됨
- **문제:** 저장 형식을 확인하려고 `state.json`을 직접 열어 값을 고치다가(따옴표를
  빠뜨리는 등) 저장했더니, 다음번 `python main.py` 실행 때 프로그램이 시작하자마자
  `json.JSONDecodeError`를 내며 게임에 들어가지도 못하고 종료됐다.
- **원인:** `load()`가 파일 내용을 그대로 `json.load()`로 신뢰해 파싱하다 보니, 형식이
  조금만 어긋나도 예외가 그대로 위로 전파돼 프로그램 전체가 비정상 종료됐다.
- **해결:** `load()`를 `try/except (json.JSONDecodeError, OSError, ValueError, KeyError,
  TypeError)`로 감싸, 손상을 감지하면 안내 메시지를 출력하고 `_use_defaults()`로 기본
  퀴즈로 복구하도록 했다. 이제 파일이 깨져 있어도 게임은 항상 실행된다. (`quiz_game.py`의 `load()`)

### 2) 게임 도중 Ctrl+C로 끄면 트레이스백이 뜨고 저장이 보장되지 않음
- **문제:** 메뉴나 정답 입력을 기다리는 중 `Ctrl+C`로 종료했더니, 빨간
  `KeyboardInterrupt` 트레이스백이 그대로 노출되며 비정상 종료됐다. 정상 종료(메뉴 6번)와
  달리 저장 단계를 거치지 않아 진행 중이던 상태가 저장된다는 보장도 없었다.
- **원인:** `input()` 대기 중 발생하는 `KeyboardInterrupt`(Ctrl+C)와 `EOFError`(입력 종료)가
  아무 데서도 처리되지 않고 최상위까지 전파됐다.
- **해결:** `main.py`에서 `game.run()`을 `try/except (KeyboardInterrupt, EOFError)`로 감싸,
  중단 신호가 와도 안내 문구를 출력하고 `game.save()`로 현재 상태를 저장한 뒤 깔끔하게
  종료하도록 했다. (`main.py`)
